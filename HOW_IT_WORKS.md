# 🧠 Как TetherVPN раздает VPN: Полный технический разбор

Это руководство объясняет внутреннее устройство и сетевую архитектуру **TetherVPN**: почему стандартная точка доступа Android не умеет раздавать VPN, как именно работает обход этого ограничения через сокетный прокси-мост, и какой путь проходит каждый сетевой пакет.

---

## 1. Главная проблема: почему Android сам по себе НЕ раздает VPN?

Когда вы включаете VPN на смартфоне, операционная система Android создает виртуальный сетевой интерфейс — **`tun0`** (TUN-интерфейс службы `VpnService`). Все установленные на телефоне приложения (Telegram, Chrome, YouTube) отправляют свой трафик в этот интерфейс `tun0`.

Но когда вы включаете **Точку доступа Wi-Fi (Мобильный хотспот)**:
```
                      ┌─────────────────────────────────┐
                      │    СМАРТФОН С АКТИВНЫМ VPN      │
                      │                                 │
[ Приложения на тел ] ──► [ Виртуальный VPN: tun0 ] ──► [ Интернет через VPN ]
                      │                                 │
[ Подключенный ПК ]   ──► [ Wi-Fi Хотспот: wlan/ap0 ] ──► [ Модем: rmnet0 (БЕЗ VPN!) ]
                      └─────────────────────────────────┘
```

1. Ядро Linux в Android жестко разделяет таблицы маршрутизации.
2. Трафик точки доступа на уровне ядра перенаправляется напрямую в сотовый модем (`rmnet_data0`), **минуя виртуальный интерфейс `tun0`**.
3. **Результат:** на самом смартфоне VPN работает, а все подключенные по Wi-Fi устройства (ПК, ноутбуки, другие телефоны) получают «голый» интернет вашего мобильного оператора — со всеми блокировками и ограничениями раздачи.

## 2. Принцип работы TetherVPN: Пользовательский мост (Proxy Bridge)

TetherVPN решает эту проблему без рут-прав, работая на уровне сокетов прикладного уровня:

```
[ ПК или 2-й телефон ]
         │
         │  1. Запрос по локальному Wi-Fi на 192.168.43.1:8080
         ▼
┌─────────────────────────────────────────────────────────────┐
│                   СМАРТФОН (TETHERVPN)                      │
│                                                             │
│  [ Входящий ServerSocket (0.0.0.0:8080) ]                   │
│         │                                                   │
│         │  2. Приложение создает исходящий сокет             │
│         ▼                                                   │
│  [ Исходящий сокет Socket(host, port) ]                     │
│         │                                                   │
│         │  3. Android отправляет сокет приложения в VPN!    │
│         ▼                                                   │
│  [ Активный интерфейс VPN: tun0 ]                           │
│  (v2rayNG / Clash / Outline / WireGuard / Amnezia)          │
└─────────────────────────────────────────────────────────────┘
         │
         │  4. Зашифрованный трафик
         ▼
[ Зарубежный сервер VPN ]
         │
         │  5. Чистый интернет
         ▼
[ Целевой сайт (например, Google / YouTube) ]
```

### Как это устроено пошагово:

1. **Сервер на смартфоне (`HttpProxyServer.kt`):**
   Приложение запускает легковесный многопоточный сервер, который слушает порт `8080` на всех адресах (`0.0.0.0`). Для подключенных устройств этот порт доступен по адресу шлюза точки доступа (обычно `192.168.43.1:8080`).

2. **Запрос от клиента (ПК или другой смартфон):**
   Клиент настраивает свой системный HTTP/HTTPS прокси на `192.168.43.1:8080`.
   Когда браузер на ПК хочет открыть сайт `https://example.com`, он отправляет команду:
   ```http
   CONNECT example.com:443 HTTP/1.1
   Host: example.com:443
   ```

3. **Магия маршрутизации Android:**
   - Получив запрос `CONNECT`, TetherVPN на телефоне выполняет обычный сетевой вызов:
     ```kotlin
     val remoteSocket = Socket("example.com", 443)
     ```
   - Поскольку сокет создается **пользовательским приложением внутри Android**, операционная система применяет к нему стандартные правила маршрутизации и **направляет его внутрь интерфейса `tun0` (вашего VPN)**!
   - Основной VPN-клиент телефона перехватывает этот сокет, упаковывает в свой протокол (VLESS, Shadowsocks, WireGuard и др.), шифрует и отправляет на удаленный сервер.

4. **Двунаправленная прокачка данных (Piping):**
   - TetherVPN отвечает ПК: `HTTP/1.1 200 Connection Established`.
   - Затем приложение открывает два параллельных потока байтов:
     - `Поток 1:` всё, что присылает ПК ➔ пересылается в сокет удаленного сервера.
     - `Поток 2:` всё, что отвечает сервер ➔ пересылается обратно в сокет ПК.
   - Для ПК это выглядит так, будто он подключен к скоростному прямому туннелю, а сотовый оператор видит только зашифрованный трафик одного-единственного приложения на смартфоне.

## 3. Путь одного сетевого пакета: от клика до экрана

Разберем конкретный пример — вы нажимаете на ссылку в браузере на ПК:

```text
[ПК: Браузер]
      │  (1) Отправка TCP пакета на 192.168.43.1:8080
      ▼
[Wi-Fi Адаптер ПК]
      │  (Радиоканал Wi-Fi)
      ▼
[Модуль Wi-Fi смартфона (Точка доступа)]
      │  (2) Передача пакета в локальный сокет порта 8080
      ▼
[TetherVPN: HttpProxyServer]
      │  (3) Читает CONNECT host:443 и открывает Socket(host, 443)
      ▼
[Сетевой стек Android]
      │  (4) Видит сокет приложения и перенаправляет в активный VpnService
      ▼
[Ваш VPN-клиент (v2rayNG / Clash / WireGuard)]
      │  (5) Шифрует пакет (AES / ChaCha20)
      ▼
[Модем смартфона (4G / 5G / LTE)]
      │  (6) Уходит через сотовую вышку оператора
      ▼
[Сервер вашего VPN за границей]
      │  (7) Расшифровывает и делает запрос к целевому сайту
      ▼
[Целевой веб-сервер]
```
Обратный ответ идет точно по этой же цепочке в обратную сторону.

## 4. Почему важно «Раздельное туннелирование» (Per-App Proxy)?

Многие пользователи сталкиваются с тем, что *«прокси открыт, но сайты не грузятся»*. Причина кроется в настройках основного VPN на смартфоне:

1. В клиентах типа **v2rayNG, Clash, Amnezia** часто включен режим **«Проксировать только выбранные приложения»** (Белый список).
2. Если в этом списке **нет галочки напротив TetherVPN**, Android посчитает сокеты TetherVPN «исключенными» и пустит их в обход VPN прямо к сотовому оператору.
3. Сотовый оператор заблокирует запрещенные ресурсы, и интернета на ПК не будет.

> **Правило:** Чтобы раздача работала, TetherVPN должен иметь право выходить в сеть **через ваш VPN-туннель**.

## 5. Зачем нужна фиксация TTL = 65 в Windows-программе?

Мобильные операторы выявляют раздачу интернета (тетеринг) по значению **TTL** (Time To Live — время жизни пакета):

- Трафик, исходящий **с самого смартфона**, имеет TTL = **64**.
- Трафик, исходящий **с компьютера Windows**, по умолчанию имеет TTL = **128**.
- Когда пакет с ПК проходит через смартфон, смартфон уменьшает его TTL на единицу: $128 - 1 = 127$.
- Оператор видит пакет с TTL = 127 и понимает: *«К телефону подключили компьютер, включаем блокировку или списываем плату за раздачу»*.

**Как защищает TetherVPN на ПК:**
Программа применяет системную команду:
```cmd
netsh int ipv4 set glob defaultcurhoplimit=65
```
Когда компьютер отправляет пакет с начальным значением **65**, телефон уменьшает его на 1:
$$65 - 1 = 64$$
Оператор видит пакет со стандартным TTL = **64** и принимает его за собственный трафик смартфона!

## 6. Как работает второй режим — «Подключение» (на другом телефоне)?

Когда вы хотите раздать VPN со смартфона **А** на смартфон **Б**:

1. **Смартфон А (Раздающий):**
   - Запускает режим **«Раздача VPN»** (сервер на `0.0.0.0:8080`).
2. **Смартфон Б (Принимающий):**
   - Подключается к Wi-Fi сети смартфона А.
   - Запускает режим **«Подключение»**.
   - Нажимает **«Шлюз Wi-Fi»** — TetherVPN считывает адрес точки доступа (обычно `192.168.43.1`).
   - Нажимает **«Подключиться к VPN»** — активируется служба `ProxyClientVpnService`:
     ```kotlin
     val proxyInfo = ProxyInfo.buildDirectProxy("192.168.43.1", 8080)
     builder.setHttpProxy(proxyInfo)
     ```
   - Android на смартфоне **Б** поднимает собственный локальный туннель и системно направляет весь веб-трафик через смартфон **А**.

## 7. Сводная таблица компонентов

| Компонент | Роль в системе | Зачем нужен |
| :--- | :--- | :--- |
| **`HttpProxyServer.kt`** | Сокетный HTTP/HTTPS сервер | Принимает трафик от подключенных клиентов и перенаправляет в сокеты телефона |
| **`ProxyForegroundService.kt`** | Фоновая служба (`dataSync`) | Удерживает `WakeLock` и `WifiLock`, не давая Android усыпить прокси при блокировке экрана |
| **`ProxyClientVpnService.kt`** | Клиентский VPN-сервис (`VpnService`) | Позволяет второму телефону без ручной настройки Wi-Fi завернуть весь свой трафик в прокси |
| **`TetherVPN.exe`** | Клиент Windows 10/11 | Автоматически находит IP смартфона, выставляет системный прокси Windows и маскирует TTL |

---

## 💡 Резюме в двух предложениях
Обычная точка доступа Android отправляет трафик подключенных устройств мимо VPN напрямую оператору. **TetherVPN** запускает локальный прокси-сервер прямо внутри смартфона, благодаря чему трафик клиентов исходит от имени мобильного приложения и автоматически заворачивается операционной системой в активный VPN-туннель.
