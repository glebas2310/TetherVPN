# 🌐 TetherVPN: Контекст проекта и техническая архитектура

> **Назначение этого документа:** единый файл контекста (System Prompt / Context File) для загрузки в любую нейросеть (LLM). Содержит полное описание архитектуры, компонентов, сетевых протоколов, принципов работы и текущего состояния проекта **TetherVPN**.

---

## 1. О проекте в двух словах
**TetherVPN** — это программный комплекс (Android-приложение + Windows-утилита), позволяющий **прозрачно раздавать активный VPN со смартфона на любые устройства** (ПК на Windows, ноутбуки, другие смартфоны) через мобильную точку доступа (Wi-Fi Hotspot) или USB-модем без ROOT-прав, а также обходить операторские ограничения на раздачу интернета (тетеринг).

* **Репозиторий проекта:** `https://github.com/glebas2310/TetherVPN`
* **Основные артефакты:** `TetherVPN.apk` (Android) и `TetherVPN.exe` (Windows).

---

## 2. Какую проблему решает проект?

### Проблема Android:
В Android при включении VPN весь трафик приложений телефона направляется в виртуальный сетевой интерфейс **`tun0`** (`VpnService`). Однако трафик точки доступа (Wi-Fi Hotspot / `ap0`) на уровне ядра Linux маршрутизируется напрямую в сотовый модем (`rmnet0`), минуя `tun0`.  
**Результат:** на телефоне VPN работает, а все подключенные по Wi-Fi устройства получают интернет напрямую от сотового оператора (с блокировками и цензурой).

### Проблема мобильных операторов (Платная раздача / Блокировка тетеринга):
Операторы определяют раздачу по значению **TTL** (Time To Live). У смартфонов TTL = 64, а у Windows по умолчанию TTL = 128. При прохождении через телефон пакет теряет единицу: $128 - 1 = 127$. Видя TTL = 127, вышка оператора блокирует раздачу или списывает деньги.

## 3. Архитектурное решение: Сокетный мост (2 Потока)

TetherVPN решает обе проблемы без ROOT-прав:

```
[ КЛИЕНТ: ПК или 2-й телефон ]
              │
              │  Поток 1: Локальный Wi-Fi (HTTP CONNECT на 192.168.43.1:8080)
              ▼
┌────────────────────────────────────────────────────────┐
│            РАЗДАЮЩИЙ СМАРТФОН (TETHERVPN)              │
│                                                        │
│  [ HttpProxyServer.kt ] (Слушает 0.0.0.0:8080)        │
│         │                                              │
│         │  Поток 2: Исходящий сокет Socket(host, port)  │
│         ▼                                              │
│  [ Сетевой стек Android ]                              │
│  (Заворачивает сокет обычного приложения в tun0)      │
│         ▼                                              │
│  [ Активный VPN-клиент ] (v2rayNG / Clash / WG)       │
│  (Шифрует пакеты в туннель к зарубежному серверу)      │
└─────────────────────────┬──────────────────────────────┘
                          │
                          │  Мобильный интернет (LTE / 5G)
                          ▼
                 [ ВЫШКА ОПЕРАТОРА ]
                          │
                          ▼
             [ ЗАРУБЕЖНЫЙ СЕРВЕР VPN ] ──► [ ЦЕЛЕВОЙ САЙТ ]
```

### Принцип работы сокетного моста:
1. **Поток 1 (Локальный):** Клиент по Wi-Fi подключается к локальному адресу смартфона (например, `192.168.43.1:8080`) и запрашивает туннель: `CONNECT host:443 HTTP/1.1`.
2. **Поток 2 (VPN):** TetherVPN на смартфоне открывает стандартный исходящий сокет `java.net.Socket(host, 443)`. Так как сокет открывается пользовательским процессом внутри Android, ОС автоматически направляет его в активный `VpnService` (`tun0`).
3. **Piping (Сквозная прокачка):** TetherVPN связывает оба сокета через буферизованные потоки байтов (16 КБ буфер, `TCP_NODELAY = true`), организуя прозрачный мост между клиентом и VPN-туннелем.

## 4. Компоненты системы

### А. Мобильное приложение (`TetherVPN.apk`)
* **Стек:** Kotlin, Android SDK 34 (Android 8.0 – 14+), Coroutines, ViewBinding, Material Components.
* **Стиль UI:** Windows 11 Fluent Dark (темная тема `#111317`, скругленные карточки `#1C1E24`, статус-бейджи).
* **Язык интерфейса:** 100% русский. Универсальное приложение (без привязки к конкретным брендам).

#### Режимы работы (2 Вкладки):
1. **Режим «Раздача VPN» (Сервер):**
   * Запускает многопоточный HTTP-прокси сервер на сокетах (`0.0.0.0:8080`).
   * Работает через **Foreground Service** (`ProxyForegroundService.kt`, тип `dataSync`) с постоянным уведомлением.
   * Удерживает **`WakeLock`** (CPU) и **`WifiLock`** (`WIFI_MODE_FULL_HIGH_PERF`), предотвращая усыпление службой энергосбережения при блокировке экрана.
   * Автоматически определяет локальный IP точки доступа (через `NetworkUtils.kt`).
   * Отображает живую статистику: количество активных соединений и трафик (↑ / ↓).
2. **Режим «Подключение» (Клиент — аналог EXE с ПК на телефон):**
   * Кнопка «Шлюз Wi-Fi» — автоматически считывает IP раздающего смартфона (Default Gateway через DHCP / LinkProperties).
   * Кнопка «Проверить прокси» (`ProxyChecker.kt`) — делает тестовый HTTP-запрос через прокси и замеряет пинг в миллисекундах.
   * Кнопка «Подключиться к VPN» (`ProxyClientVpnService.kt`) — поднимает системный Android `VpnService` с параметром `setHttpProxy(ProxyInfo.buildDirectProxy(host, port))` (Android 10+), системно направляя весь интернет второго телефона через прокси первого.
   * Кнопка быстрого перехода в системные настройки Wi-Fi для ручного ввода прокси.

### Б. Программа для компьютера (`TetherVPN.exe`)
* **Стек:** Python 3.15, CustomTkinter (Fluent Dark), PyInstaller (`--onefile --windowed --uac-admin`).
* **Исходник:** `proxy_switcher.py`, скрипт сборки `build_exe.py`.
* **Функционал:**
  1. **Автопоиск прокси в локальной сети:** многопоточное сканирование кандидатов шлюза (`192.168.43.1`, шлюзы из `ipconfig`, соседние узлы ARP) на открытый порт 8080 с контрольной проверкой пропуска VPN-пакетов.
  2. **Системное проксирование Windows:**
     * WinINet в реестре (`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` ➔ `ProxyEnable = 1`, `ProxyServer = IP:PORT`).
     * Оповещение подсистемы через Windows API `InternetSetOptionW` (`INTERNET_OPTION_SETTINGS_CHANGED`, `INTERNET_OPTION_REFRESH`).
     * Системный WinHTTP (`netsh winhttp set proxy IP:PORT`).
     * Git-прокси (`git config --global http.proxy IP:PORT`).
     * Переменные среды окружения (`HTTP_PROXY`, `HTTPS_PROXY` через `setx`).
  3. **Маскировка TTL от операторов:**
     * Выполняет `netsh int ipv4 set glob defaultcurhoplimit=65`.
     * Компьютер отправляет пакет с TTL = 65. При прохождении через смартфон TTL уменьшается на 1:
       $$65 - 1 = 64$$
     * Оператор видит стандартный TTL = 64 (как у самого смартфона) и не применяет блокировок / тарификации раздачи.
  4. **Безопасный возврат:** в один клик отключает прокси во всех уровнях Windows (реестр, WinHTTP, Git, переменные) и возвращает стандартный TTL = 128.

## 6. Важные эксплуатационные правила

1. **Раздельное туннелирование (Per-App Proxy):**  
   Если в основном VPN на телефоне (v2rayNG, Clash, Outline) включен режим *«Проксировать только выбранные приложения»*, в этот список **обязательно должен быть добавлен TetherVPN**. Иначе сокеты TetherVPN пойдут мимо VPN в открытый интернет сотового оператора.
2. **Разрешение локальной сети (Allow LAN):**  
   В некоторых VPN-клиентах требуется включить переключатель *«Разрешить подключения из локальной сети»* (Allow LAN / Bypass LAN).
3. **Состояние репозитория GitHub:**  
   В публичной ветке `main` на GitHub лежат 3 файла для конечных пользователей: `TetherVPN.exe`, `TetherVPN.apk`, `README.md`. Все исходные коды разработки хранятся локально на рабочей машине.
